# 记忆轮转归档方法论

> 本文档定义 `.skill-memory/` 目录的生命周期管理，由 team-orchestrator 的 **Step 7** 调用。
> 适用范围：当前项目 cwd 下**所有** `.skill-memory/*/` 目录（含 team-orchestrator 自身与 13 个角色 skill）。

## 一、设计目标

- **防堆积**：过期日报不再无限累积为 write-only 死文件
- **冷热分离**：
  - `MEMORY.md` = 热记忆（Step 0 每次必读，只放可复用决策）
  - `archive/YYYY-MM.md` = 冷记忆（按需读，保留每日摘要）
- **沉淀**：归档时把可复用决策提取到 `MEMORY.md`，避免历史日志中 buried 的关键决策丢失
- **可追溯**：月度归档保留每日 1-3 行摘要，仍可按月按日检索

## 二、默认参数（v1）

| 参数 | 默认值 | 理由 |
|------|--------|------|
| 年龄阈值 | 30 天 | 覆盖一个冲刺周期 + "继续/补/上次"延续语义窗口 |
| 归档粒度 | 月度 `archive/YYYY-MM.md` | 12 篇/年，文件数低；与 30 天阈值天然对齐 |
| 数量硬上限 | 35 篇日报 | 稳态约 30-31 篇 + 当月 4-5 篇缓冲，避免误触发 |
| 每日摘要长度 | 1-3 行 | 压缩约 95% 体积仍可按月检索 |
| MEMORY.md 提取 | 按主题分类、每条 1-2 行 | 与各 skill 现有 MEMORY.md 规范一致 |
| Step 0 冷记忆回读 | 仅最近 1 个月度归档 | 控制加载成本，避免全量加载 |

## 三、目录与归档文件结构

```
.skill-memory/{skill}/
├── 2026-07-31.md          # 活跃日报（≤30 天，保留原文）
├── ...
├── MEMORY.md              # 长期热记忆（Step 0 必读）
└── archive/
    ├── 2026-05.md         # 月度归档（冷，保留每日摘要）
    └── 2026-06.md
```

## 四、月度归档文件模板

```markdown
# {skill 展示名} 记忆归档 · {YYYY-MM}

> 由 team-orchestrator 记忆轮转归档机制于 {归档执行日期} 生成。
> 来源：{YYYY-MM} 月共 {N} 篇日报（原文件已删除）。
> 可复用决策已同步至 ../MEMORY.md；本文件仅保留每日摘要。

## 归档摘要
- 归档日报数：{N}
- 时间范围：{最早日期} ~ {最晚日期}
- 提取至 MEMORY.md 条目数：{M}

## 每日摘要

### {YYYY-MM-DD}
- 场景/产出：{1-2 行}
- 关键决策：{1 行}

### {YYYY-MM-DD}
- ...
```

## 五、轮转算法（执行步骤）

### 5.1 轻量检查（每次 Step 7 必做）

1. 枚举当前项目 cwd 下所有 `.skill-memory/*/` 目录
2. 对每个目录统计「待评估日报」= 文件名匹配 `^\d{4}-\d{2}-\d{2}\.md$` 的文件（**排除** `archive/` 子目录、`MEMORY.md`、`.DS_Store` 等）
3. 触发完整轮转的条件（满足任一即对该目录进入 5.2）：
   - **条件 A（年龄）**：存在日报日期 < 今天 − 30 天
   - **条件 B（数量）**：该目录待评估日报数 > 35
4. 所有目录均不满足 → 输出一行「记忆轮转：无需归档（已检查 {N} 个 skill 目录）」，结束

### 5.2 单目录完整轮转（对每个命中的 `.skill-memory/{skill}/` 执行）

1. 列出该目录全部 `YYYY-MM-DD.md`，按日期升序
2. 计算「应归档集合」：
   - 优先取「日期 < 今天 − 30 天」的全部日报
   - 若仅因条件 B 触发（年龄不满足），则取最早的 K 篇使剩余 ≤ 30（K = 当前数 − 30）
3. 按「年-月」分组：同一 `YYYY-MM` 归入同一 `archive/YYYY-MM.md`
4. 对每个分组顺序处理：
   1. 读取该组每篇日报，提取「每日摘要」：1-2 行场景/产出 + 1 行关键决策
   2. 读取或新建 `archive/YYYY-MM.md`（用第四节模板）
   3. **幂等去重**：若 archive 中已存在 `### {该日期}` 节 → 跳过该日追加（防止重跑双写）
   4. 将每日摘要按日期升序追加到 `## 每日摘要` 末尾
   5. **同步提取可复用决策**：符合该 skill `MEMORY.md` 既有主题分类的条目（如产品为 商业模式/竞品/画像/策略/Roadmap；orchestrator 为 规范/偏好/路由）
   6. 对 `MEMORY.md` **去重追加**：若已存在语义相近条目（关键词重合）→ 更新；否则在对应主题节追加，无匹配主题则归入新建 `## 其他` 节
   7. 更新 `archive/YYYY-MM.md` 的「归档摘要」计数与时间范围
5. **删除已成功写入 archive 的原日报文件**（仅删除 4.4 成功的，失败则保留）
6. 输出单目录归档摘要：`{skill}: 归档 {N} 篇 → archive/{YYYY-MM}.md（{M} 条入 MEMORY.md）`

### 5.3 归档后校验

- [ ] `archive/YYYY-MM.md` 存在且含对应每日摘要
- [ ] `MEMORY.md` 已追加可复用条目且无重复
- [ ] 原日报文件已删除
- [ ] 该目录剩余日报数 ≤ 30
- [ ] 归档动作已记一行入 `.skill-memory/team-orchestrator/{今天}.md`

## 六、覆盖范围与边界

**覆盖**：当前项目 cwd 下所有 `.skill-memory/*/`（含 orchestrator 自身 + 13 角色 + 任何其他已写入的 skill），与"该 skill 是否被本次调度"无关——只要项目里偶尔跑一次 orchestrator，所有角色 skill 的记忆都会被顺带轮转。

**不覆盖（v1 已知限制）**：从未在该项目 cwd 运行过 orchestrator 的纯独立角色 skill 使用场景。未来 v2 可在角色 skill 的 Step 6 末尾加一行 opt-in 引用本文件。

**边界处理**：
- **空日报**：仍归档，摘要写「无实质产出」，不报错
- **长期内容误入日报**（如日报内出现 `## 项目约定` 段）：抽取至 `MEMORY.md` 对应主题，archive 仅留摘要
- **跨月边界**：7 月 31 日触发时，7 月 1 日报若满 30 天 → 归入 `archive/2026-07.md`（与当月仍活跃的日报共存于不同位置：归档的在 archive/，活跃的在根目录，无命名冲突）
- **当月日报**：通常尚未满 30 天，留在根目录；当月不主动归档

## 七、首次运行安全开关

- 若该项目 `.skill-memory/*/archive/` **全部不存在**（首次轮转）→ Step 7 输出「将归档 {N} 篇日报，涉及 {M} 个 skill 目录」后**暂停请求用户确认**，确认后再删除原日报
- 后续运行（已存在 `archive/`）→ 自动执行，不每次询问
